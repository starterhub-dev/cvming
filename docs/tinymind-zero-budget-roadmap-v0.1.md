# TinyMind 零预算模型实验路线 v0.1

目标：在不购买 API 额度、不公开密钥的前提下，先验证 TinyMind 的人格、评测流程和小模型实验路径。

## 当前状态

- [x] 静态聊天网页已发布到 GitHub Pages。
- [x] 人格宪章已建立。
- [x] 30 道人格与原则评测题已建立。
- [ ] 尚未接入可用的模型推理服务。
- [ ] 尚未跑通免费模型的端到端聊天。
- [ ] 尚未进行学生模型微调。

注意：网页部署成功不代表模型服务可用。当前 Supabase Edge Function 会在缺少模型密钥时返回配置提示。不要把 API 密钥写进前端、GitHub 文件或公开日志。

## 阶段 1：不依赖模型，先验证评测体系

1. 将 30 道评测题整理成统一格式：输入、目标行为、评分标准、风险等级。
2. 每次测试保存模型名、提示词版本、输出、分数、失败原因。
3. 将评测分为两类：
   - 人格表达：幽默、接梗、简洁、语气适配。
   - 判断可靠性：证据、拒答、认真帮助、新闻事实与评论分离、纠错。
4. 先人工评估基线，暂不自动把另一个模型的打分当成最终真相。
5. 每次修改人格规则后重跑同一套题，比较差异。

## 阶段 2：寻找可免费试用的推理服务

候选路线（实际额度、地区可用性、服务条款和模型清单都需要当时核验）：

- Hugging Face 的公开模型演示或 Spaces：适合试验，但可能排队、休眠或有调用限制。
- 提供免费额度的模型推理平台：只使用明确允许个人实验的免费额度，并记录限制和到期条件。
- Google Colab：适合短时间运行小模型、做实验和测试；不适合作为始终在线的生产后端。
- 本地运行开源小模型：若以后有可用电脑或云端免费算力，可尝试量化模型；当前手机不适合承担大模型持续推理。

选择标准：
1. 免费条件明确，避免自动扣费。
2. 服务条款允许当前用途。
3. 支持可调用的推理接口，或可在 Colab 中运行。
4. 模型许可允许实验和计划中的发布方式。
5. 不向不可信服务发送敏感个人数据。

## 阶段 3：先在 Colab 验证，再接网页

1. 选一个体量较小、许可清晰的开源指令模型。
2. 在 Colab 中运行最小推理示例。
3. 用 30 道评测题测试模型的基础行为。
4. 加入 TinyMind 人格指令，再跑同一套题，比较前后差异。
5. 保存实验结果与资源消耗，不将 Colab 临时会话当作永久服务。
6. 只有确认某个推理服务可用且符合条件后，再设计 Supabase Edge Function 适配层。

## 阶段 4：接入 TinyMind 网页

后端适配层应当：
- 只在服务端保存访问令牌。
- 设置超时、错误处理和基本速率限制。
- 限制单次输入与上下文长度，避免免费额度被耗尽。
- 对外返回清晰的错误信息，不泄露密钥或供应商内部细节。
- 在未配置模型服务时明确显示“模型暂不可用”，不伪装成真实 AI 已回答。

## 阶段 5：再研究微调

先不要把人格提示词、训练数据和模型微调混为一谈。按顺序推进：

1. 先建立高质量示范回答。
2. 为每条样本记录用户输入、上下文、期望行为和理由。
3. 去重并剔除隐私、错误事实、群体偏见与互相矛盾的样本。
4. 先比较提示词优化的效果。
5. 只有当样本数量、算力和模型许可都合适时，再尝试 LoRA/QLoRA 等参数高效微调。
6. 微调前后必须跑同一套回归评测，检查是否出现能力退化。

## 成功定义

第一阶段成功不是“TinyMind 已经拥有自己的大脑”，而是：我们能在免费实验环境中运行一个模型、用固定评测集检验人格表现、保存实验记录，并明确知道下一步需要改进什么。
